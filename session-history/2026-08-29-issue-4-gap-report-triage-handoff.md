## 3. Important Decisions

**Decision: reject all 20 items in the issue #4 report as written; take no content-build action.**
- **Reason:** `tradeindustriesgroup.com.au` is a 217-page general renovation *and*
  disaster-restoration company (kitchens, extensions, commercial/shop fit-outs, offices, attic
  conversions, water/fire damage restoration) — not a like-for-like bathroom-renovation
  competitor. 6 of the 20 items are services ETR does not offer and has not been asked to add. One
  item ("Water Damage and Fire Damage Restoration") would re-litigate the standing D-02 decision
  (no standalone waterproofing/repair services) with zero new evidence. The report supplies **no
  search volume or difficulty data for any of the 20 items**, and checks gaps in one direction
  only. Two of the remaining items (a bathroom cost guide, a small-bathroom page) were **already**
  on the content roadmap in `docs/SEO_CONTENT_GUIDE.md` §2 priority 6, from before this report
  existed — so the report added no new evidence for those either, and nothing changes about when
  they get built.
- **Alternatives considered:** Building the "top priority" items the report itself flagged
  (renovation cost guides, kitchen planning, commercial fit-out, small-space renovations, budget
  ideas) — rejected because most are out of scope and none has volume evidence.
- **Why the chosen approach (reject-and-record) was preferred:** This is the exact process
  `docs/SEO_CONTENT_GUIDE.md` §3 prescribes for this report type, and it is the same process an
  earlier session in this same day already used successfully for the near-identical issue #3
  report (D-85/D-86) — reusing that precedent kept the two decisions consistent and easy to find
  together.

**Decision: name the new source PDF
`docs/source-copy/pdf/topic-gap-report-2026-08-10-tradeindustriesgroup.pdf` instead of reusing the
issue-3 filename.**
- **Reason:** both reports were generated by the same tool on the same date (2026-08-10), so the
  issue-3 filename (`topic-gap-report-2026-08-10.pdf`, no competitor name) would have collided.
- **Alternatives considered:** overwriting/renaming the issue-3 file to disambiguate it
  retroactively — rejected as out of scope for this task and risked touching another session's
  in-progress commit.

## 4. Permanent Rules / Lessons

- **This project will keep receiving these gap-report issues.** Two arrived the same day (issues
  #3 and #4), both from the same third-party tool, both branded with the same `HeyTony.ca`
  content-strategy pitch, both against a mismatched "competitor" (a large multi-trade generalist,
  not a bathroom specialist), both with zero volume/difficulty data. **Treat any future issue
  titled "gaps" with a PDF attachment as this same report type by default** — check it against
  `docs/SEO_CONTENT_GUIDE.md` §3 before doing anything else, and check `DECISIONS.md` §3e/§3f for
  precedent before re-deriving the triage from scratch.
- **These reports' own site-comparison numbers for ETR are consistently stale/wrong** (both
  issue #3 and issue #4 undercounted the live page count by roughly half or more). That alone is
  useful independent evidence the tool is not crawling live, so don't take its counts at face
  value even for sanity-checking.
- **When two decisions are clearly the same shape** (same report type, same day, same rejection
  logic), mirroring the exact structure of the first (same section-heading pattern, same six-point
  process, same table format) makes the pair much easier for a future session to find and compare
  side by side — worth the small extra effort over writing a differently-shaped entry.
